## 操作

| 输入 | 作用 |
|---|---|
| **点击画面** | 锁定鼠标（锁定后视角才响应鼠标） |
| **Esc** | 释放鼠标 |
| 鼠标移动 | 模拟手机的 yaw / pitch（物理角） |
| Q / E | roll |
| 鼠标左键 | 右拇指击发区 |
| 鼠标右键 | 左拇指击发区 |
| R | 重定心 |
| F1 | 显示/隐藏诊断 HUD |
| F2 | 显示/隐藏调参面板（会自动释放鼠标） |
| F5 | 重开一局 |

一次完整扫视约需 800 像素，不锁定光标会在窗口边缘卡住——表现出来像"转不动了"，很容易被误判成判定或滤波的问题。

真机横屏：左右各 28% 宽为触发区，中央为捕获区。Pulse 音符任一触发区点击即可；Point 需要点在音符投影附近（Editor 下退化为 Pulse，因为只有一个鼠标既要瞄准又要点击）。

## 输出文件

都在 `%USERPROFILE%\AppData\LocalLow\SpatialRhythm\SpatialRhythmGreybox\`：

- `session_*.csv` — 每次判定一行，27 列，含当时的完整参数快照

调参面板里可以「开始录姿态 / 停止并保存 / 回放最近一段」。**真机录一次，Editor 里反复回放调参**，不用反复出包。

## 核心循环

**引导线牵着你转 → 音符在固定坐标原地生成 → 交互。**

- 音符钉在自己的空间坐标上，**不会飞向你**。从小长到实际大小，判定时刻最大
- 一条贴在球面上的弧线穿过后续音符，一个光点按 dspTime 沿线前进
- 你的任务是**用准星跟住光点**——跟住了，音符就正好在你面前长到实际大小
- 引导线向前看 4 拍，音符只提前 2 拍出现：**线先到，音符后现**

这条关系是刻意的。让音符自己飞到眼前会毁掉"寻找"，而主动转过去发现音符是这套输入唯一不可替代的乐趣。

引导线就是设计文档 §7.2 的"视线编舞曲线"——在编辑器里是作者画的辅助线，在游戏里是玩家看见的路径，两者是同一条数据。

## 关于"移动"

**首版没有位移，只有旋转。** 这是设计文档 §0 的地基结论：IMU 双积分求位置在手机上不可用（10 秒漂 25 米），所以判定活在角度空间里，相机固定在原点。玩家的"移动"就是转动设备本身。

唯一的例外是**肩关节杠杆视差**（§0.2）：

```
p_camera = q_physical * (0, 0, -r)      r ≈ 0.5 m
```

从姿态四元数派生的小幅相机位移，零漂移。**它不参与任何判定。**

实现上有个必须注意的坑：如果只是简单地平移相机，12m 处音符的屏幕位置会相对判定方向偏移 `atan(0.5/12) ≈ 2.4°`——和 `θ_perfect`（2.5°）同量级，准星对准了判定却说没对准，"所见即所判"直接被破坏。

所以这里的做法是：**音符与引导线跟随相机原点渲染**，它们相对相机的方向恒等于判定方向；只有星空（14–70m，距离拉开以产生差异视差）会相对移动。这样视差幅度可以随便调，永远污染不到判定。

F2 面板里可以开关、调臂长和幅度；幅度 >1.0 会标注"已夸张"。前庭敏感时直接关掉。

## 关键实现口径

写代码时钉死的几条，改动前请先读设计文档对应章节：

| 口径 | 位置 |
|---|---|
| θ_virt = G · θ_phys，角度笼/容差用虚拟角，体力预算用物理角 | `Presentation/GainMapper.cs` |
| 双锥：θ_activate 二元门槛 + θ_perfect 满分区 | `Judging/JudgeService.cs` |
| 辅助瞄准只扩激活锥，不影响 SpatialQuality | `JudgeService.Evaluate` |
| 空间表现分取触发瞬间，不取窗口均值 | 同上 |
| 判定按触摸时间戳从 PresentedPoseHistory 回溯 | `Chart/ChartPlayer.HandleTrigger` |
| dspTime 是唯一主时钟 | `Audio/Conductor.cs` |
| 深度不参与判定 | `Judging/NoteEvent.cs` |

## 已知限制

- **触摸时间戳是帧时间，不是 OS 时间戳** —— HUD 会黄字告警，CSV 的 `osTimestamp` 列记 0。这是 Stage 4 的第一个待验证项。
- **渲染管线是 Built-in 而非 URP** —— 灰盒只有无光照方块，管线对画面和延迟主项都无影响。升级成真实切片时再换。
- **Point 音符在 Editor 下不可靠** —— 只有一个鼠标，无法复现双拇指。
- **P0 的三条指标一条都不能在 Editor 里测** —— 抖动、端到端延迟、手臂疲劳全部只有 iOS 真机能测。Editor 阶段只验证逻辑正确性与参数敏感度。

## Editor 阶段该怎么用

1. F2 打开调参面板，开「注入模拟手抖」（0.3° / 4Hz）
2. 切换 One Euro 开关，看 HUD 的静止抖动 P95 变化
3. 跑完一遍谱面，F5 重开，换 G 值再跑
4. 对比两份 `session_*.csv` 的脱锁率与时间偏差分布

谱面刻意扫过三档物理角速度（约 40 / 90 / 190 °/s）加一段边界压力测试，用来找"多快开始靠运气"的拐点。它不追求好玩，也不对应任何音乐。
